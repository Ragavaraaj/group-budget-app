# Testing and quality

Counts: **147** shared, **220** server and **287** web unit tests, and **189** end-to-end tests (50 written with M0 to M4, and 139 added since for validation and negative flows).

- **`packages/shared` (Vitest + fast-check)**: property tests — splits always sum to total and are fair to within one paisa; balances across a group sum to zero; suggested transfers fully clear balances in ≤ n−1 payments; ids are valid UUIDv7 and sort by time; paise parsing/formatting round-trips; **reporting periods tile the calendar with no gap or overlap for every start day 1–28, and every date falls in its own period and financial year**; recurring dates never repeat or go backwards and clamp the 31st and 29 February correctly; category totals always add up to the total; the schemas accept and refuse what they should (an expense whose split doesn't add up, 11 mutations in a push, duplicate mutation ids).
- **`apps/server` (Vitest 4 + `@cloudflare/vitest-pool-workers`)**: tests run **inside `workerd`**, the real Workers runtime, against a simulated D1 that has the real migrations applied (`vitest.config.ts` + `test/apply-migrations.ts`). They call the Hono app through a small cookie-keeping `Client` (`test/helpers.ts`) and also `SELF.fetch` through the real Worker entry. Covers: config (dev login impossible in production), the schema and the batch-atomicity guarantee, **auth** (dev login, sessions and sliding expiry, CSRF, the whole Google flow with Google's token endpoint mocked: PKCE, state single use, sign-up gate, invites expired/revoked/used up, ID-token checks, attempt-login including confirm, one-time redeem, expiry and the same-browser case), **sync** (idempotent and concurrent pushes, last-writer-wins, conflict flag, delete wins, restore, authorization and id-hijack attempts, references, full 10-mutation push, paging across tables, backfill, removal, name changes reaching group-mates) and **groups/invites** (limits, ownership rules, rejoin, the guarded join raced by two people for the last use or place, removal that an invite cannot undo, adding back, stopping links one by one or all, handing a group over (and two hand-overs racing leave exactly one owner), deleting a group (everything erased, every member removed with a distinct change number, other groups untouched), people without the app). **Budgets and recurring rules** go through the push tests like any entity (references, tombstones, per-group limits, the server working out the next due date, pause and resume). **The recurring job** is tested for idempotence (two runs racing for one occurrence write one expense, one audit row and one report; a rule edited or deleted after the run read it gets nothing, and the edit is used next time; an edit that moves the next date back is not made twice), catching up in capped runs, skipping paused, deleted, ended and orphaned rules and rules that name someone who left (without taking a place from another rule), a member taking over a rule whose creator left, a rule picking up from the day a returning member came back (and never reaching further back than the 93-day floor), an Undo the same day being lossless, a delete and its Undo arriving together at the group limit, keeping the template's split exactly, the audit trail, and its **statement count against the free plan's 50-query limit**. **The live hub** is tested with real WebSockets inside `workerd`: connecting needs a session, the app's own origin and a valid id; a push wakes group-mates but not the pushing device (while waking that person's other devices) and nobody outside the group; a duplicate push wakes no one; group changes, removals, deletions and the recurring job all notify; the message carries no data; ping is answered; a person's oldest connections are closed beyond eight. Also: a push that fails for any reason other than the duplicate-mutation race is not retried, an invalid configuration answers a clean 500 (with a negative control showing the test fails without the fix), starting a sign-in writes exactly one row, and an invite survives the installed-app hand-off. Pull tests also assert D1's `meta.rows_read` (a counting wrapper around the binding): a poll with no news scans a small constant number of rows however large the history, a poll after a few changes scans in proportion to them, and a first page of a ~900-expense account stays under 400 rows, so a missing index fails a test instead of burning quota.
- **`apps/web` (Vitest + `fake-indexeddb`, Node)**: the local write path (local row + outbox in one transaction, base-version chaining), applying pulled rows (never over unsent edits or newer rows, removal, backfill rules), the **sync engine against a scripted server** (a refused change is undone locally: new rows removed, edited rows restored from the server; chunking, ordering, offline, network and server errors, 401, rejections, conflicts, isolating a malformed change, paging, backfill and resume, coalescing, polling interval and back-off with fake timers, hidden-tab behaviour, no sync for a connection closed in the background or after the engine stopped), the split logic, balances/activity derivation, CSV export (formula defusing), date formatting. **The live channel** against a fake socket and fake timers (backoff 1 s, 2 s, 4 s … a minute and reset once it works, no reconnect loop after the server closes it for too many connections, giving up on a socket that never opens, ping and giving up on silence, closing in the background and reconnecting, ignoring a replaced socket), the engine's live mode (news syncs at once, polling slows while live, normal pace and one catch-up sync when it drops), **CSV parsing** (quotes, line breaks in cells, BOM, three separators), **bank statement reading** (Indian dates and amounts, a credit card's sign guess by majority, narrations that only contain a keyword's letters such as TORRENT POWER, five bank-shaped sample headers, a table below account details, credits left out, unreadable lines counted, duplicates, narration to category), search filtering, how a schedule is described (and who has left a rule), what a budget can still be set for, category naming for charts (a category called "Other" or "None" stays apart from the rows the app adds), and the Dexie upgrade that clears the pull cursor. The React components themselves are covered by the end-to-end tests.
- **E2E (Playwright, Chromium, Pixel 7 profile)**: runs against `wrangler dev` serving the **built** web app and the API from one origin, which is how production behaves; the e2e server starts with `ENVIRONMENT=development` and `ENABLE_DEV_LOGIN=1` and a persisted local D1, and each test uses a fresh email address. Specs: installability, offline reload and deep-link, headers and **zero CSP violations** across the app's screens (`pwa`, `security-headers`); sign-in through the Google stand-in, sign-out wiping the local database, "not invited", the **installed app signing in through a second browser context** (the page the app would have opened is captured, the app stays waiting until the person confirms in the other browser), and a session ending while changes are queued (`auth`); adding, editing, deleting with undo, **adding offline → reloading offline → reconnecting → appearing on a second device**, changes appearing on another device, categories, CSV export (`ledger`); and **two people running a trip so the balances match a hand calculation**, exact/percent/shares splits, invite → join, removal, an owner-removed person refused by the link until added back, stopping links (all, and one at a time), handing a group over and then leaving, deleting a group for everyone, a person without the app in the balances, leaving held back while changes are unsent, an invite used by someone not yet signed in, a bad invite (`groups`); **insights** (totals, category split, comparison with the month before, the financial-year view, your share versus the whole group), **search** across months (`insights`); **budgets** (warning at 85%, going over, editing, undo, appearing on a second device), **recurring expenses** made by the scheduled job (triggered through `wrangler dev --test-scheduled`) exactly once and seen on a second device, pausing, and the **month start day** (`planning`); a **bank statement import** with a credit and unreadable lines left out, duplicates flagged on a second import, a column corrected, and a non-statement refused (`import`); and **live updates**: the connection comes up under the CSP, an expense added on another device appears with no reload, and being removed from a group is noticed within seconds (`live`). The CSP test now visits every screen, including those, with the WebSocket open.
- **E2E: validation and negative flows** (added after M4). The earlier specs show the app doing the right thing; these show it refusing the wrong thing, and are where a regression is most likely to hide. Each file is one area:
  - `expense-form`: every unreadable, zero, negative or too-large amount is refused and the accepted spellings (`12.`, `.5`, `₹ 1,23,456.78`) are understood; the 200-character note; no future dates; unsaved edits; deleted and made-up expenses open the not-found page; undo; the remembered category.
  - `split-rules`: each split type (equal, exact, percent, shares) and several payers: what is refused, the message shown, and that a saved split gives the balances a hand calculation gives.
  - `group-management`: group and person name rules, owner-only controls as a member sees them, rename, the delete confirmation, settle-up (refused amounts, part and over-payment, undo), edits and deletes by another member shown in Activity, someone who left, owner actions with no connection, the join page's every error message (including a group that has not reached the phone, or only half of it), and addresses for groups the person is not in.
  - `auth-negative` and `api-authorization`: sign-in refusals, made-up and replayed sessions, requests from another origin, OAuth callback abuse, the installed app's hand-off, and the Worker called directly as an owner, a member and an outsider (owner-only actions, reading or writing a group you are not in, a removed member, malformed bodies and ids, every endpoint asking for a sign-in, the live WebSocket's guards, and the 50-people and 30-groups limits).
  - `categories`, `planning-validation`, `import-limits`, `search-and-navigation`, `settings`, `sync-and-export`: category rename, archive and delete; budget lines at 79.9%, 80% and 100%; recurring rules (end before start, the three-month limit, a rule held back when someone it names has left); files the import cannot use; search filters and an empty result; insights periods; the tab bar and not-found pages; the month start day; a failing server, a dropped connection, a refused change, a conflicting edit from two devices; and what the CSV and JSON exports contain.
  - `layout` and `design-system`: nothing a person types may push a screen sideways on a 360 px phone, and every drop-down is the shadcn Select.
  - **Expected failures.** A test for a bug that is still open is marked `test.fail(true, 'BUG-nnn: …')`. It shows as "passed" while the bug exists and **fails once the bug is fixed**, which is the cue to remove the mark and move the entry in [Known bugs](known-bugs.md) to "Fixed". None are open today: BUG-001 to BUG-005 are all fixed.
  - The tests were checked the other way too: breaking the CSRF origin check, the expense form's Save condition, and the owner check on renaming a group each made the matching tests fail.
- **What the tests do not cover**: Google's real servers (the token exchange is mocked), real iPhones and Safari/WebKit (only Chromium is run; a one-off run of the built app in WebKitGTK 2.52, the engine family Safari is built on, driven with Selenium on a virtual display, covered sign-in, sync, a push and a reload, joining a group through the backfill, a first sync of 360 expenses, the group flow again over HTTPS with `Secure` cookies and the live WebSocket under the CSP, and an app update. It is not part of CI), a real Cloudflare deployment and its limits (the Durable Object, the hourly trigger and the R2 workflow have only run locally), real bank statements, rate limiting at Cloudflare.
- **Static**: strict TypeScript and **Biome** (lint, format, import order) with `noRestrictedImports` enforcing the boundaries in [Repository layout](repository-layout.md). Biome replaced ESLint + Prettier; it doesn't format Markdown/YAML.
- **CI gates**: TS-only guard, Biome, typecheck (regenerates Worker types), unit tests, a dry-run bundle of the Worker, production-dependency audit, and the e2e job; a merge to `main` then deploys ([Infrastructure](infrastructure.md)). The backup workflow is separate and scheduled.
- **Noise in the e2e log**: `[WebServer] ✘ [ERROR] kj::getCaughtExceptionAsKj() = ... disconnected: write(): Broken pipe (os error 32)` appears a few times per run, locally and in CI. It is `workerd` writing to a connection the browser has already closed (a test's context ending with a WebSocket or request in flight), not a failing test: the run still ends with every test passing and the step green. Look at the Playwright summary line, not at that message.
- **Audit**: CI audits production dependencies at `high`. A plain `npm audit` is also clean: the dev-tooling advisories (`undici` and `sharp` inside `miniflare`, `esbuild` inside `drizzle-kit`) are pinned with `overrides` in the root `package.json`; drop an override once the package that pulls it in depends on a fixed version itself.
