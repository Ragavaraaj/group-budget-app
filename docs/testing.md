# Testing and quality

Counts are as of the end of M2: **84** shared, **122** server, **113** web unit tests and **21** end-to-end tests.

- **`packages/shared` (Vitest + fast-check)**: property tests — splits always sum to total and are fair to within one paisa; balances across a group sum to zero; suggested transfers fully clear balances in ≤ n−1 payments; ids are valid UUIDv7 and sort by time; paise parsing/formatting round-trips; the schemas accept and refuse what they should (an expense whose split doesn't add up, 11 mutations in a push, duplicate mutation ids).
- **`apps/server` (Vitest 4 + `@cloudflare/vitest-pool-workers`)**: tests run **inside `workerd`**, the real Workers runtime, against a simulated D1 that has the real migrations applied (`vitest.config.ts` + `test/apply-migrations.ts`). They call the Hono app through a small cookie-keeping `Client` (`test/helpers.ts`) and also `SELF.fetch` through the real Worker entry. Covers: config (dev login impossible in production), the schema and the batch-atomicity guarantee, **auth** (dev login, sessions and sliding expiry, CSRF, the whole Google flow with Google's token endpoint mocked: PKCE, state single use, sign-up gate, invites expired/revoked/used up, ID-token checks, attempt-login including confirm, one-time redeem, expiry and the same-browser case), **sync** (idempotent and concurrent pushes, last-writer-wins, conflict flag, delete wins, restore, authorization and id-hijack attempts, references, full 10-mutation push, paging across tables, backfill, removal, name changes reaching group-mates) and **groups/invites** (limits, ownership rules, rejoin). Pull tests also assert D1's `meta.rows_read` (a counting wrapper around the binding): a poll with no news scans a small constant number of rows however large the history, a poll after a few changes scans in proportion to them, and a first page of a ~900-expense account stays under 400 rows, so a missing index fails a test instead of burning quota.
- **`apps/web` (Vitest + `fake-indexeddb`, Node)**: the local write path (local row + outbox in one transaction, base-version chaining), applying pulled rows (never over unsent edits or newer rows, removal, backfill rules), the **sync engine against a scripted server** (chunking, ordering, offline, network and server errors, 401, rejections, conflicts, isolating a malformed change, paging, backfill and resume, coalescing, polling interval and back-off with fake timers, hidden-tab behaviour), the split logic, balances/activity derivation, CSV export (formula defusing), date formatting. The React components themselves are covered by the end-to-end tests.
- **E2E (Playwright, Chromium, Pixel 7 profile)**: runs against `wrangler dev` serving the **built** web app and the API from one origin, which is how production behaves; the e2e server starts with `ENVIRONMENT=development` and `ENABLE_DEV_LOGIN=1` and a persisted local D1, and each test uses a fresh email address. Specs: installability, offline reload and deep-link, headers and **zero CSP violations** across the app's screens (`pwa`, `security-headers`); sign-in through the Google stand-in, sign-out wiping the local database, "not invited", the **installed app signing in through a second browser context** (the page the app would have opened is captured, the app stays waiting until the person confirms in the other browser), and a session ending while changes are queued (`auth`); adding, editing, deleting with undo, **adding offline → reloading offline → reconnecting → appearing on a second device**, changes appearing on another device, categories, CSV export (`ledger`); and **two people running a trip so the balances match a hand calculation**, exact/percent/shares splits, invite → join, removal, an invite used by someone not yet signed in, a bad invite (`groups`).
- **What the tests do not cover**: Google's real servers (the token exchange is mocked), real iPhones and Safari/WebKit (only Chromium is run), a real Cloudflare deployment and its limits, rate limiting at Cloudflare.
- **Static**: strict TypeScript and **Biome** (lint, format, import order) with `noRestrictedImports` enforcing the boundaries in [Repository layout](repository-layout.md). Biome replaced ESLint + Prettier; it doesn't format Markdown/YAML.
- **CI gates**: TS-only guard, Biome, typecheck (regenerates Worker types), unit tests, a dry-run bundle of the Worker, production-dependency audit, and the e2e job; a merge to `main` then deploys ([Infrastructure](infrastructure.md)).
