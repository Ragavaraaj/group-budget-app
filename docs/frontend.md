# Frontend

- **Shell and routing**: React Router; the whole shell is precached by the service worker. Mobile-first with a bottom tab bar (Expenses, Groups, Settings) and an always-visible sync-status chip on top. Add/edit expense is a _route_ (not a modal) so the Android back button behaves.
- **Routes**: `/login`, `/join/:token` (outside the sign-in gate; the join page works before sign-in), and behind it: `/` (personal ledger by month), `/add` (`?group=`), `/expenses/:id/edit`, `/insights` (`?group=`; loaded lazily), `/search` (`?group=`), `/budgets` (`?group=`), `/groups`, `/groups/:id` (tabs: Expenses, Balances, Activity, Members, kept in `?tab=`), `/settings`, `/settings/categories`, `/settings/recurring` (+ `/new`, `/:id`), `/settings/import`. The bottom bar has four tabs: Expenses, Insights, Groups, Settings. Behind the gate, a provider opens the person's own local database and starts their sync engine; signed out, everything redirects to `/login`.
- **State**: Dexie live queries are the source of truth (`db/hooks.ts`). Local React state for UI only. No Redux. A tiny typed `fetch` wrapper (`lib/api.ts`, distinguishing "the network failed" from "the server said no") for the online-only calls: auth, group management, invites.
- **UI kit**: **shadcn/ui** components live in `apps/web/src/components/ui` (copied from the shadcn repo, then ours to edit), configured through `components.json` and an `@/` path alias. Tailwind v4 with dark mode following the OS. In use: button, card, badge, skeleton, sonner, input, label, select, tabs, dialog, alert-dialog, avatar, checkbox, switch, toggle-group (separator, dropdown-menu and textarea are copied in but not used yet; calendar/popover are not used: dates use the native date input; chart is for M3). **Forms use plain React state plus the shared zod schemas and the pure split logic**, not react-hook-form: the one complex form (the split editor) keeps what was typed as text and resolves it with `resolveSplit` (`features/expenses/split-draft.ts`, unit-tested), and the simple ones didn't need a form library.
- **Charts**: drawn by hand in SVG (`features/insights/charts.tsx`), not with Recharts/shadcn charts. The screens need only bars, so this adds no dependency and about 9 KB for the whole lazily loaded Insights chunk; it needs no inline `<style>` (shadcn's chart component injects one, which the CSP would have forced us to rewrite); and each chart gives a screen reader its figures as a label and a list. The Insights route is loaded on first use and precached, so it works offline.
- **UX priorities** (this is what makes expense apps stick), and where they stand:
  - amount-first entry in ≤3 taps: **done** (the amount field has focus on open; category is one tap and remembered per group; date defaults to today);
  - always-visible sync status ("Synced", "Syncing", "Offline · 2 waiting", "Sync problem", "Sign in to sync"): **done**;
  - undo on delete (toast with Undo, for expenses and payments): **done**;
  - defaults from last-used category: **done**; last-used payer/group: not done;
  - fast list with virtualization once it exceeds a few thousand rows: not done (the list is per month, so it stays short);
  - search and filters: **done** (a Search screen across months and groups: words in the note, category name, amount or date, plus category, date range and amount range);
  - budgets and spending insights: **done**.

**Screens as built**

- _Expenses_ (personal ledger): month navigator, month total, expenses grouped by day, floating add button. A row not yet sent says "Not synced yet".
- _Add / edit expense_: amount, category chips, date, note, group (when in more than one). In a shared group also **Paid by** (one person, or several with amounts), and **Split**: Equally (tick who is in), Exact amounts, Percent, Shares, with live feedback ("₹600 left to assign") and each person's resulting amount. Everything is saved to the local database first; if the browser refuses that write (storage full, a blocked database) the form stays as it is with a message, so nothing typed is lost (`lib/local-errors.ts` wraps every local write the UI makes).
- _Groups_: your groups with where you stand in each; create a group (needs a connection). _Group_: expenses by month; **Balances** (your balance, everyone's, the fewest payments that settle up, record a payment, payments made with undo); **Activity** (who added, edited or deleted what); **Members** (invite link, "Stop links" to end every open link, remove, "Add back" for people the owner removed, leave; leaving first sends anything waiting and is held back, with a message, while changes in the group can't be sent).
- _Join_: shows who invited you to which group, signs you in if needed (the invite carries through Google), then "Join group".
- _Insights_: a month (or an Indian financial year, April to March) with its total, the per-day or per-month average, how it compares with the period before, a six-month or twelve-month bar chart, the split by category (the same category name in several groups is added up), and, for one group, the budgets closest to their limit. By default it counts **your share** of shared expenses; for one shared group a toggle shows the whole group.
- _Search_: find expenses by words, category, dates and amount range, across all months and groups, with a total; tapping a result edits it and returns to the search.
- _Budgets_: monthly limits for a group, overall or per category, each with a progress bar (a warning at 80%, "over" at 100%); alerts appear above the Expenses screen and a group's expenses. Worked out on the device, so they appear offline. Budgets count the group's whole spending.
- _Recurring expenses_: rules for rent, subscriptions or an investment (weekly, monthly or yearly, with an optional end date, the same split editor as an expense in a shared group, pause and delete with undo). The server creates the expenses, hourly.
- _Import from CSV_: choose a bank statement; the file is read on the device. Columns are recognised by their headers (HDFC, ICICI, SBI, Axis and Kotak layouts, or any file with a date and debit, credit or amount columns), the table is found below account details, Indian dates and amounts (`02/10/26`, `1,23,456.78`, `Dr`/`Cr`) are understood, a preview lists what will be imported with a category suggested from the narration, rows that look already recorded (same day and amount) are unticked, money coming in is left out, and each column can be corrected before importing. Spending goes into the personal ledger; at most 500 rows per import.
- _Members_ (owner extras): open invite links with a "Stop" beside each (and "Stop all links"), "Add someone without the app", a crown to hand the group over, and "Delete group" (the group's name must be typed).
- _Settings_: account, sync (last synced, waiting count, whether the live connection is up, "Sync now", changes the server refused), categories, budgets, recurring expenses, import, **the day a month starts on** (1 to 28, for salary cycles; a setting on this device that the Expenses, Insights and Budgets screens follow), export (CSV, JSON), install, server status, sign out.

**PWA specifics**

- `vite-plugin-pwa`, starting in `generateSW` mode (precache + navigation fallback), switching to `injectManifest` only when the sync engine needs a custom service worker. It hasn't needed to.
- Caching: precache shell + assets; `/api/*` is never cached by the service worker (the sync engine owns it) and the Worker sends `Cache-Control: no-store` on API responses.
- Static-asset headers live in `apps/web/public/_headers` (Cloudflare applies them): hashed `/assets/*` are `immutable`; everything else keeps Cloudflare's default of revalidating, which is what lets installed PWAs pick up new versions.
- Update flow: a browser keeps running the version it has until an update is activated, and a plain reload does not do that (the new version just waits; this was reproduced in WebKit), so someone who reloads without tapping the message could stay on old code indefinitely. An update found **right after the app opens** (within 10 s) is therefore applied at once, since nothing can be half-entered yet; a second automatic update within a minute of the first is asked about instead, so it can never reload in a loop (`src/pwa/update-policy.ts`). One found later (a tab left open for hours) still shows "A new version is available" with a Reload, and is never applied mid-entry. Settings shows which version the app itself is (`app <commit>`, baked in at build time from `GITHUB_SHA`; `dev` for a local build) next to the server's, and says so when the app is older than the server.
- Manifest: `standalone`, 192/512/maskable icons, `apple-touch-icon`. (The app shortcut "Add expense" is not added yet.)
- `navigator.storage.persist()` is requested on sign-in. Safari can evict IndexedDB for non-installed sites; the server remains the source of truth, so eviction is recoverable by re-pulling, but un-synced outbox items would be lost, which is why flush-on-foreground matters.
- iOS caveats: push works only for installed PWAs (16.4+); no Background Sync; sign-in uses attempt-login in standalone mode ([Auth](auth.md)); install from Chrome via Add to Home Screen, since non-installed use loses the service worker and risks storage eviction.
